# 3. Method

This section describes the SparseFormer architecture, the adaptive locality prior that generates per-query sparsity masks, and the training procedure that allows the discrete mask to be learned end-to-end with standard backpropagation.

## 3.1 Notation and overview

Let `X ∈ R^{n×d}` denote the input to a SparseFormer attention layer, where `n` is the sequence length and `d` is the hidden dimension. The layer projects `X` into query, key, and value matrices `Q, K, V ∈ R^{n×d}` using the usual learned linear maps. In a standard transformer, attention is computed as `softmax(Q K^T / sqrt(d)) V`, which materialises the full `n × n` attention matrix and is responsible for the dominant `O(n^2)` memory term.

SparseFormer replaces this dense product with a sparse one. For each query position `i`, we compute a binary mask `m_i ∈ {0, 1}^n` that indicates which key positions should participate in the attention computation. The output for query `i` is then `softmax((q_i · K_{S_i}^T) / sqrt(d)) V_{S_i}`, where `S_i = {j : m_i[j] = 1}` is the active key set. The cardinality of `S_i` is bounded by a hyperparameter `k`, typically set to `min(128, 0.1 n)`. The expected memory cost of attention thus drops from `O(n^2)` to `O(n k)`, yielding the headline VRAM savings reported in this paper.

## 3.2 The adaptive locality prior

Generating a useful mask `m_i` is the central technical challenge. A naïve approach — selecting the `k` keys with the largest dot product to `q_i` — would require materialising the full `n × n` score matrix and would therefore defeat the purpose of sparsification. Instead, we use a lightweight predictor that we call the *adaptive locality prior* (ALP).

The ALP is a two-layer feed-forward network operating on a compact feature vector `φ_i ∈ R^{d'}` that summarises everything the model knows about query `i` at the current layer. The feature vector concatenates three signals: (a) a learned projection of `q_i` itself; (b) a sinusoidal embedding of the position `i`; and (c) a global context summary, computed as an exponentially-decayed running average of the layer's input across all positions. The ALP outputs a score vector `s_i ∈ R^B`, where `B` is a fixed number of *position buckets* — contiguous spans of the sequence that the mask treats as atomic. Mask generation then selects the top-`k/b` buckets by score and unions their member positions, where `b` is the bucket size.

The bucket abstraction is a critical engineering choice. By predicting scores at the bucket level rather than per position, the ALP runs in `O(n B / b)` time and `O(B)` memory, both of which are dwarfed by the cost of the sparse attention itself. The bucket size `b` is set adaptively: short sequences use small buckets to preserve precision, while longer sequences use larger buckets to amortise the prior's overhead. Empirically, we find that `b = 64` is a good default for sequences in the 16k–128k range.

## 3.3 Differentiable mask training

Discrete top-`k` selection is not differentiable, but the buckets and their scores are, so we need only ensure that gradients flow through the score function. We adopt a straight-through estimator: in the forward pass, the mask is generated by hard top-`k` selection over the bucket scores; in the backward pass, we treat the mask as if it had been generated by a soft `softmax` over the same scores, and propagate gradients accordingly. This estimator is biased but low-variance, and we find it is sufficient to learn high-quality masks within the first 10% of pretraining steps.

We additionally regularise the prior with two auxiliary losses. The *coverage loss* penalises queries whose selected key set excludes any key with a true attention weight (computed using a teacher dense attention layer that we run intermittently) above a threshold; this prevents the prior from converging to a degenerate local-only solution. The *load-balancing loss* encourages each bucket to be selected with roughly equal frequency across the batch, which prevents pathological imbalances that would harm hardware utilisation.

## 3.4 Hardware-aware kernel

Sparse attention on modern GPUs is bandwidth-bound rather than compute-bound, so naïve implementations of the algorithm above can leave substantial performance on the table. We provide a custom CUDA kernel that materialises the active key/value blocks in shared memory before invoking the attention computation, avoiding redundant global-memory traffic. The kernel supports arbitrary bucket sizes that are a multiple of the warp size, and it exploits the FlashAttention-style fused softmax-and-multiplication kernel for the dense submatrix at each bucket.

The combination of architectural sparsity, the lightweight ALP, and the hardware-aware kernel is what enables SparseFormer to deliver real wall-clock savings rather than the merely asymptotic improvements typical of prior efficient-attention methods.
